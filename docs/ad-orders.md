# 广告订单台账

后台入口为「经营 → 广告订单」（`/ad-orders`）。原「用户 → 兑换记录」不受影响。投放列表里的「订单」可只看该广告的合作记录，并直接新建关联订单。

## 记录内容

广告主、联系方式、订单名称、购买位置、北京时间档期、人民币约定金额、备注及可选关联广告。订单位置和日期是合同快照；与实际广告不一致时详情页提示核对。

保存订单不预留广告位，不自动创建、延期或暂停广告，也不发起真实支付。收退款必须在实际完成后人工登记。更新投放须在详情页单独检查并确认。

## 金额与流水

- 数据库以整数分保存金额，输入最多两位小数。允许金额 0 的免费合作。
- 支持多次收款，每笔保留日期、方式、流水号与备注。不能收超待收金额，不能退超净实收，也不能登记未来日期。
- 付款状态由实际流水推导：未收款、部分收款、已收齐、已全额退款。
- 收款和退款不可直接覆盖或删除，误记收款可通过退款冲回；真实的后续收款另行登记。
- 取消订单保留合同和流水，停止新增收款与合同编辑，允许退回尚未退完的金额。取消不会改变关联广告的投放。
- 列表总览跨全部订单计算：未取消合同金额、全部订单累计净实收、未取消订单待收，以及取消订单尚未退回的净实收。

## 续费与并发

「登记续费」新建订单并保留原订单关系，默认沿用广告主、广告、位置、金额，接续原到期日。新档期不得早于原到期日，续费广告须与原订单相同；更换广告另建订单。原合同不会被续费覆盖。

详情页「续费与投放衔接」先读取最新订单、广告和容量，展示当前与更新后的具体位置、起止日期，再点「确认更新关联广告」。同位置连续续费保留原开始日，延长到新到期日；素材、链接、收款保持原样，并记录更新前后档期。已覆盖的合同无需重复同步。

暂停、取消、已结束订单、尚未结束的广告换位置、以及原档尚未结束且新旧档期存在空档时会阻止同步，避免提前换位或把空档也展示出来。原档结束后可同步新的完整档期。已有更晚投放不能被旧订单截短。未收齐会提示，但允许管理员明确安排投放。

预览不改广告。确认时在写事务中核对预览对应的订单版本及广告内容，并再次检查整个档期容量，防止预览后被改动或新增竞争广告。重复提交不会重复延长或增加日志。

新增订单及收退款使用提交编号防止重试重复写入，重复编号携带不同内容会被拒绝。合同修改与取消校验版本，防止覆盖他人的新修改；数据库写事务再次核对余额，防止并发收超或退超。

## 私有接口

均需管理员会话，写入还需 `X-Ops: 1`，不进入前台公开广告接口或发布快照。

- `GET/POST /api/ad-orders`：列表、新建。列表可按 `q`、`ad_id`、`status`、`payment_status`、`page`、`size` 筛选。
- `GET/POST /api/ad-orders/{id}`：详情、修改，修改提交 `version`。
- `POST /api/ad-orders/{id}/payments`：`kind=receipt/refund`、`amount`、`paid_on`、`method`、`reference`、`note`、`request_key`。
- `POST /api/ad-orders/{id}/cancel`：提交当前 `version`。
- `GET /api/ad-orders/{id}/report?mode=human|all|ai`：效果报告，默认过滤后流量。
- `GET /api/ads/calendar?month=YYYY-MM`：月排期与逐日物理位置占用。
- `GET /api/ad-orders/{id}/delivery-preview`：检查并预览关联广告安排。
- `POST /api/ad-orders/{id}/delivery`：提交 `preview_token` 和 `request_key`，确认更新。

## 广告效果报告

订单列表「报告」或详情「查看报告」进入 `/ad-orders/{id}/report`。按该订单广告、购买位置和北京时间档期查询，开始日包含、到期日不包含，只取截至生成日的记录。首页、站点列表、投票及其他已记录页面分开，具体位置和路径列在明细中。点击率按总点击除总曝光计算，零曝光不计算；逐日表只列实际有记录的日期。

广告位交付、站内收录入口补充数据、历史位置未分类单独展示，不相加冒充交付。同广告重叠合同会提示数据不能唯一拆到某一笔订单。过滤后的流量排除已识别 AI、自动化和未知事件，不承诺全是真人，数据也不是独立访客或注册成交。

报告页面以三项广告位指标、每日趋势、页面贡献和位置明细呈现。曝光 / 点击切换同时作用于趋势图与页面贡献；贡献占比以该指标在所有页面的总和为分母。趋势图只连接相邻且均有记录的日期，缺少记录的日期留空，单个日期显示真实数据点。指向或聚焦数据点可看具体数字，空数据不绘制虚构曲线。明细分为广告位和收录入口两个标签，统计说明默认折叠，打印时包含两种明细及逐日记录。

可下载独立 HTML 报告、CSV 明细，以及通过打印存为 PDF。导出保留广告主、订单号、约定档期、口径和位置，不带联系方式、合作金额、内部备注和流水。HTML 对文本转义，CSV 防止标签被识别为公式。报告接口仍要求管理员登录，不生成公开分享链接。

顶部以三个直接切换的选项选择过滤后、全部或 AI 流量，支持方向键切换，并显示各口径说明。右侧「导出报告」菜单选择 HTML 报告或 CSV 明细，打印 / PDF 独立保留；刷新、切换口径与打印会关闭导出菜单。

## 广告位排期

「经营 → 广告排期」或投放管理「排期日历」进入 `/ad-calendar`。按月切换、点日期查看广告名称、到期撤下和待安排订单。左右角标容量 2，列表顶部 4，页脚不限名额；组合套餐计入每个实际位置。

已安排只计未暂停广告的实际档期，到期日 00:00 释放名额。订单尚未由关联广告覆盖的日期单列「待安排」，不虚占名额。该区也提醒接单时核对未落实的合作。手机显示紧凑日期及占用提示，选中日期后查看完整余量。

## 验证

```powershell
python -m unittest discover -s server -p test_ad_orders.py
python -m unittest discover -s server -p test_ad_campaigns.py
python -m unittest discover -s server -p test_ops.py
node scripts/ad-report-export.test.mjs
npm run build --prefix admin
node scripts/ad-orders-ui.test.mjs
node scripts/ad-report-ui.test.mjs
```

浏览器验证使用 `PLAYWRIGHT_MODULE` 指定 Playwright；访问本地管理界面但拦截全部接口，连接独立临时 SQLite 和临时后台，覆盖建单、收退款、失败重试、续费预览与确认、排期边界、采集归因、HTML/CSV 下载、打印、下拉框及桌面和手机布局。不会修改真实广告或账目。可用 `AD_ORDERS_ADMIN_URL`、`AD_ORDERS_QA_OUTPUT` 更改界面地址和截图目录。

`ad-report-ui.test.mjs` 仅用拦截的示例报告，覆盖非连续日期趋势、指标切换、键盘提示、贡献占比、分区明细、打印、空数据、失败重试及不同宽度的筛选控件；截图可用 `REPORT_QA_OUTPUT` 指定，示例数据不会写入真实库。
